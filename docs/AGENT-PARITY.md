# Agent 能力对照：LocM 与 LocModel 3.3.0

## 结论

LocM 的 Agent **不等同于 LocModel**。LocM 有本地模型任务循环、工作区文件工具和命令审批流程；它没有接入 MCP、网页/浏览器工具或电脑操作，也没有操作系统级进程沙箱。此次已修复一个可确定的安全差距：命令、覆盖和删除现在必须通过 Rust 后端发起的系统原生确认，不能只靠前端按钮拦截。

## LocM 已有能力与限制

- 调用当前已启动的本地模型，以 JSON 工具协议完成多轮任务；新任务和追加要求先展示计划。
- 文件列表、读取、创建与修改限定在用户选择的工作区；文件工具拒绝符号链接和 `.git` 元数据。读取上限为 1 MiB，单次列目录最多 500 项、深度最多 6 层。
- 覆盖、删除和运行命令会先显示 Agent 操作预览，再由 Rust 后端弹出系统原生 Yes/No 确认。覆盖确认展示新内容预览、字节数和 SHA-256；命令确认展示程序、精确参数数组、工作目录与权限风险。取消后该操作不执行，任务暂停。
- 任务记录在 WebView 本地存储；未接入 MCP、网页搜索/浏览器、电脑控制或跨工作区工具。

**重要边界：** 命令仍以当前用户权限运行并继承环境变量，可访问工作区以外的文件和网络，也可能启动子进程。工作目录和系统确认都不构成操作系统沙箱；直接子进程超时也不保证清理其后代进程。

## LocModel 包对照的验证限度

检查对象为用户提供的 `LocModel_3.3.0_amd64.deb`；SHA-256 与提供值一致：`894dc1caf612d6de0bbb1f85ac9c6979b25ea9ce934344223c4e4f6a021d5a33`。包内只有 LocModel 可执行文件、图标和桌面入口。静态字符串可识别 `/agent.js`、`/agentpage.js`、`tool_run_command`、若干 tool/web 标识，以及 `src/computer.rs` 等模块名；这些只能证明包内有相应资源或代码标识，不能单独证明页面实际启用了哪些功能、审批如何工作或每项能力都可运行。

为了实际查看页面，曾在禁网、隔离 HOME、清空环境变量的图形沙箱中尝试启动包内程序两次；两次均在窗口出现前以退出码 139 结束。未登录、未启动模型或引擎、未下载权重，也未触发文件操作。由于没有成功打开 Agent 页面，本次**不能声称已完成 LocModel 页面交互级对照，也不能声称 LocM 与 LocModel 完全等同**。该包没有被安装到系统。

## 本次改动

LocM 的 UI 审批卡保留为操作预览；实际执行危险操作时，`agent_write_file`、`agent_delete_file` 和 `agent_run_command` 的后端处理器会再弹出系统原生确认。后端取消结果会明确返回给 UI，任务暂停而不继续调用工具。这个改动加强了确认边界，但不会限制经确认命令的操作系统权限；若要实现真正隔离，还需要独立进程沙箱与严格的资源权限设计。

本次源码通过 23 项默认测试与 58 项桌面测试，Linux x86_64 release 构建与 Windows x64 GNU 交叉构建均成功。Windows 包包含 `WebView2Loader.dll`，但没有在真实 Windows 设备启动验证。测试包仅在本机交付，没有创建新 Release，也没有把包、二进制或模型权重提交到源码仓库。
