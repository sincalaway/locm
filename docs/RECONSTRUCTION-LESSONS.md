# LocModel 重建版经验与 LocM 改进

## 结论

[`single2339/LocModel`](https://github.com/single2339/LocModel/tree/25cedf35a03612b55a3712edd804351dc3d10ea9) 是一个独立的 Rust/Tauri 重建项目，README 将其标为 LocModel 3.1.0 重建版；它不是原版 LocModel 源码。值得借鉴的是把“已有引擎/模型 → 参数准备 → 子进程启动 → `/health` 就绪 → 聊天”做成连贯的桌面流程，而不是把重建版里每个页面或工具名称都当成已验证能力。

## 值得借鉴的产品经验

- **允许复用现有推理引擎，减少重复下载。** 重建版的 [`src/engine.rs`](https://github.com/single2339/LocModel/blob/25cedf35a03612b55a3712edd804351dc3d10ea9/src/engine.rs) 会先检查保存的 `server_path`，并支持环境变量及 `PATH` 中的 llama-server；其设置页也提供选择已有引擎目录。这个路径对已经准备好本地运行环境的用户很实用。
- **启动成功应以健康检查为准。** 重建版启动子进程后轮询本机 `/health`，而不是把“进程已创建”当作服务可用（同上，`start` 生命周期）。LocM 已有此原则：只有健康检查成功后才报告模型启动就绪。
- **把能力与证据分开呈现。** 重建版 README 明确指出图像/视频流程只由本地协议服务验证，真实扩散模型未验证；Agent/API、桌面输入授权和多 GPU 等也有实测边界。应继续区分“代码入口存在”“Mock/协议验证”“真实模型验证”和“目标系统实机验证”。

## 本次已落实到 LocM

设置页新增“复用已有 llama-server”：用户可明确选择一个 `llama-server`（Windows 为 `llama-server.exe`）文件。LocM 将其规范化并校验文件名/可执行权限，保存到本机设置；能力探测和启动都会优先使用该路径。清空后回退到 LocM 引擎管理中的最新安装版本。无效或已移除的自定义路径会明确报错，不会悄悄切换到另一个二进制。

这采用了“显式选择”而非自动扫描 `PATH`，避免环境中多个版本时意外启动错误版本。参数仍只依据所选二进制 `--help` 的实际输出；LocM 不安装或更新用户选定的文件。当前 LocM 仍以 CPU 参数启动，因此这项改进**不等于启用 GPU 推理**，也没有承诺任意外部构建或模型都兼容。

设置字段是可选且具备反序列化默认值，旧版 `settings.json` 无需迁移即可继续使用。实现位置：`src/desktop_backend.rs`、`src/bin/desktop.rs`、`ui/index.html`、`ui/app.js`。

## 不照搬的做法与后续方向

重建版的局域网模式使用 `0.0.0.0`（`src/engine.rs`）；LocM 继续只绑定回环地址，用户明确开启后也只选一个私有 IPv4 地址。LocM 还保留更严格的官方引擎下载摘要校验、安全解包与 Agent 危险操作确认，不以重建版的简化导入/执行路径替代这些边界。

后续可考虑借鉴“分阶段启动诊断与最近日志”，以及用极小本地服务/模型夹具覆盖启动、健康检查、聊天、停止、崩溃、超时和端口占用；它们需要独立设计与回归，不属于本次外部引擎接入。账号、支付、会员线路、品牌资产和未经实测的网页/电脑 Agent 能力不在 LocM 本次迁移范围内。
